# Known Divergences — Reading the Catalog

The [catalog](../known-divergences.md) is generated by
`scripts/generate_divergences_catalog.py` from published capability
manifestations. Do not edit the generated catalog by hand.

## Authority and identity

A divergence is a scoped behavioral claim, not an upstream issue ID.
Its identity is the combination of:

- **Scope:** one backend family or explicit dialect.
- **Target:** an operation, protocol method, public composition, or native
  construction entrypoint supported by the target inventory.
- **Scenario:** immutable argument, option, input schema/data, and execution
  descriptors. Null, NaN, and missing information remain distinct.

Each occupied home under
`src/mountainash/{expressions,relations}/backends/capabilities/` publishes its
local `SEGMENT`. Directory structure fixes the backend, family/dialect,
Substrait/extension namespace, and domain. Publication derives source locations;
authors do not add origin fields or maintain a second global divergence list.

A manifestation records classification, expected and observed behavior, impact,
workaround, and declaration date. Outcomes may be historical claims or retained
observations; historical prose is not fresh execution evidence. The declaration
date is not an inferred affected-version interval.

An optional explicit issue reference joins metadata in
`registry/upstream-issues.yaml`. Issue status, links, and root-cause metadata do
not create behavioral claims or determine their identity. Source-only issues
can remain open without a qualified manifestation.

## Local authoring and stored access

For example, the `narwhals/dialects/narwhals_pandas/substrait/string.py`
home owns the following local shape. The surrounding `_scope.py` supplies
`Scope(CONST_BACKEND.NARWHALS, Dialect("narwhals-pandas"))`; neither the
manifestation nor its key repeats backend or domain fields.

```python
from mountainash.core.capabilities.declarations import (
    CapabilitySegment, DivergenceManifestation, Domain, ManifestationKey,
)
from mountainash.core.capabilities.schema import (
    CaptureValue as C, DivergenceKind, EntrypointStage, OperationTarget, Scenario,
)
from mountainash.expressions.core.expression_system.function_keys.enums import (
    FKEY_SUBSTRAIT_SCALAR_STRING as STRING,
)

SEGMENT = CapabilitySegment(
    domain=Domain.STRING,
    capabilities=(),
    manifestations=(
        DivergenceManifestation(
            key=ManifestationKey(
                OperationTarget(STRING.STARTS_WITH),
                Scenario(
                    arguments=(("input", C.of({"expression": "field", "column": "text"})),
                               ("substring", C.of("x"))),
                    options=(("case_sensitivity", C.of("CASE_INSENSITIVE_ASCII")),),
                    input_schema=(("columns", C.of({"text": {"type": "text", "nullable": True}})),),
                    input_data=(("fixture", C.of({"text": [None, "anchor"]})),),
                    execution=(("stage", C.of(EntrypointStage.MATERIALIZATION)),),
                ),
            ),
            kind=DivergenceKind.SEMANTICS,
            expected=C.of([None, False]),
            observed=C.of([False, False]),
            impact="Null input becomes False rather than propagating null.",
            since="2026-09-17",
        ),
    ),
)
```

This illustrates a local declaration, not a replacement for other rows already
owned by that module. A retained probe is supplied separately as evidence.
`register_segment()` accepts a validated `BoundSegment` and publishes it
atomically; `register_backend()` retains its existing runtime-fact contract.

```python
from mountainash.core.capabilities.catalogue import CatalogueQuery, ManifestationQuery
from mountainash.core.capabilities.identity import Dialect, Scope
from mountainash.core.capabilities.registry import CapabilityRegistry
from mountainash.core.constants import CONST_BACKEND

scope = Scope(CONST_BACKEND.NARWHALS, Dialect("narwhals-pandas"))
capture = CapabilityRegistry.capture(scopes=frozenset({scope}))
rows = capture.search(CatalogueQuery(manifestations=ManifestationQuery())).manifestations
record = rows[0]
assert capture.reader(scope).get(record.key.local) == record
```

Stored readers are exact: `get()` raises on a miss, `get_optional()` returns
`None`, and neither falls back from a dialect to its family. Effective compiler
lookups still apply their existing family/dialect refinement rules. A capture
keeps its original generation after registration or snapshot restoration.

Structural WindowSpec and CAST defaults are effective values: omitted and
explicit defaults are equivalent for their gates. Scalar argument binding
continues to distinguish supplied operands from omitted ones.

## Observations and tests

The test-owned `tests/fixtures/_manifestation_observers.py` associates exact
test functions and parameter cells with qualified manifestation keys.
`tests/fixtures/verification_bindings.py` captures the selected claim payload,
its source bytes, the observer, the independent oracle address, and execution
stage. Runtime compilation does not import this test data or execute observers.

Selected operational failures are classified only during the test call.
A matching concrete declared exception class is an expected failure; subclasses
do not match implicitly. An unexpected pass fails a strict expectation. Wrong
exception types, fixture setup failures, and teardown failures remain ordinary
failures. Unrelated parameter cells remain unmarked.

Every observer covered by a complete directory, file, class, or method selection
must match exactly one collected parameter cell. Matching occurs before backend,
`-k`, and `-m` deselection. Explicit parameter-node selection does not require
unselected cells. Relative selections resolve from the invocation directory.

Direct native observations are separate from operational expectations.
Retained JSON captures include source, fixtures, package/engine coordinates,
layer, stage, and results. A Mountainash capability refusal is not evidence of
native backend behavior. Readers validate a digest of the complete assertion and
the retained source bytes, rather than borrowing a later catalogue origin.
Original observation timestamps remain unchanged; later assertion qualification
has its own timestamp. Changed claim payloads are rejected rather than silently
receiving old results.

Missing evidence is distinct from an explicitly captured empty result.
Captured data remains readable after later registry publication or retirement;
a cold capture does not discover or execute new tests.

## Adding a claim

1. Recover the actual failing provider cell, callable/operation, arguments,
   options, fixture, and stage. Use a composition target when the observer
   executes a public composition rather than one operation.
2. Put the declaration in its physical scoped `SEGMENT`. Split independently
   shaped scenarios and dialects; do not broaden a provider alias into a family.
3. Record source-supported expected and observed behavior. Mark unavailable
   historical outcomes explicitly; do not invent native results or version
   intervals.
4. Associate an existing operational observer by exact natural key, or retain a
   direct probe with its real source and environment. Do not bind an unrelated
   passing test as proof.
5. Add an explicit upstream issue join only when that issue describes this
   claim. Upstream issue IDs remain metadata, not selectors.
6. Regenerate and check the reports.

## Correcting or retiring a claim

A newly passing scenario does not prove every related operation or dialect is
fixed. Preserve the complete prior payload and source identity in an
`AssertionChange`, with the actual correction evidence and disposition. Narrow
or remove only the affected claim, remove its obsolete operational expectation,
and retain the positive result as evidence.

Do not infer a backend fixed-version range from one installed environment.
Do not close an upstream issue solely because a local declaration was corrected
or retired. Reference-only historical cases remain outside active publication
until their target and scenario can be recovered.

## Maintenance commands

```bash
# Regenerate capability projections and the manifestation catalog
python -m mountainash.core.capabilities.render_markdown
python scripts/generate_divergences_catalog.py

# Check the generated catalog and issue metadata
python scripts/generate_divergences_catalog.py --check
python scripts/validate_upstream_registry.py
python scripts/audit_upstream_issues.py --skip-github

# Network-backed upstream reconciliation, when explicitly requested
python scripts/audit_upstream_issues.py --report-file scripts/outputs/reconciliation-report.md
```

See also [backend architecture](backend-architecture.md) and the enforced
cross-backend consistency and upstream-fix-monitoring principles.
